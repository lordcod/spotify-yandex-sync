# Spotify ↔ Яндекс: синхронизация новых лайков

Проект переносит лайки в обе стороны. Аудио не скачивается.
Поддерживаются только Spotify Liked Songs и «Мне нравится» Яндекс.Музыки.

## Установка и авторизация

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run.py init
```

В `config.yaml` укажи `spotify.client_id` своего Spotify-приложения.
В настройках приложения зарегистрируй redirect URI `http://127.0.0.1:8787/callback`.
Client Secret не нужен: используется OAuth PKCE.

```powershell
python run.py auth spotify
python run.py auth yandex
```

Spotify запрашивает `user-library-read user-library-modify`.
Если старому токену не хватает доступа к записи, повтори авторизацию.
Yandex-токен тоже нужно получить заново при истечении срока действия.
Токены находятся в `data/`, не публикуй их.

## Настройка

```yaml
playlists:
  - name: liked
    source: likes
    sync_mode: mirror
    initial_limit: 20
```

- При первоначальном запуске обрабатываются только последние 20 лайков **каждого** сервиса.
  Это максимум 20 исходных треков с каждой стороны, а не 20 гарантированных совпадений.
- Остальная старая библиотека запоминается как пропущенная. Последующие запуски
  не импортируют следующие порции старых треков.
- Новые лайки после первоначального запуска переносятся в обе стороны.
- `initial_limit: 0` начинает синхронизацию только с будущих лайков.
- Изменение `initial_limit` после первого запуска не сбрасывает список пропущенных треков.
- Старый пропущенный трек станет новым, если снять лайк, выполнить синхронизацию,
  затем поставить лайк снова. Действия между запусками без промежуточного снимка не различаются.
- `mirror` переносит снятие лайка только для уже синхронизированных пар.
  Если такая пара осталась с одной стороны, побеждает удаление.
- `add_only` не переносит удаления и восстанавливает снятые лайки у управляемых пар.
- Ненайденные новые треки сохраняются и повторно ищутся при следующем запуске.

Старая пара противоположных настроек с одинаковым именем автоматически преобразуется
в одну задачу. Другие источники и несколько задач не поддерживаются.
Существующие синхронизированные пары сохраняются при обновлении.

## Запуск

```powershell
python run.py sync liked
```

`python run.py sync` и `python run.py sync all` запускают ту же единственную задачу.
`python run.py list` показывает её настройки.

Для запуска после включения VPN:

```powershell
python wait_and_sync.py
```

Скрипт проверяет страну внешнего IP через ipinfo.io каждые 15 секунд и запускает
синхронизацию, когда страна отличается от RU. Сам VPN он не включает.

Запускай только один процесс синхронизации одновременно.

## Состояние и восстановление

`data/sync.db` содержит:

- `track_map` — кэш соответствий между сервисами;
- `likes_sync_state` — управляемые пары и незавершённый план;
- `likes_ignored` — старые лайки, которые не нужно импортировать;
- `sync_runs` — история запусков.

План сохраняется перед изменениями в сервисах. После сбоя он повторяется до
завершения, затем читаются новые изменения. Действия пользователя во время
незавершённого плана могут быть перекрыты его повторным выполнением.
Старые таблицы в существующей базе не удаляются, но больше не используются.
Не удаляй базу для перезапуска: это сбрасывает историю и список пропущенных треков.

## Поиск совпадений

Сравниваются название, исполнители, длительность и альбом. Совпадение должно
набрать `matching.min_score` (по умолчанию 86). Сомнительные результаты
`best rejected` не переносятся. Возможны ошибки сопоставления разных версий песни.

Между поисковыми запросами к Яндексу — пауза 1 секунду. Настройка:
`matching.yandex_search_interval_seconds`. При 429, временных серверных ошибках
и таймаутах выполняются пять повторов с паузами 2, 4, 8, 16 и 32 секунды.
Ошибки авторизации и исчерпание повторов останавливают запуск, не помечая трек
как отсутствующий в каталоге.

## Проверка кода

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временные базы и подставные клиенты, не меняя реальные лайки.
